Eat Raw Data

4

Chomp The Noise

  • Vendor: Execute Transform → Format → Trim. Then Clean.
  • Amount: Replace Values $ → (blank). Replace , → (blank).
  • Amount: Mutate Data Type to Decimal Number.
QUESTION: What happens if we skip the 'Trim' step on the Vendor names?

> ANSWER: Computers are literal. A leading space makes it an entirely different string. " STAPLES " will not match with "STAPLES" in our alias map. Trimming invisible whitespace is the #1 fix for failed joins.
5

Temporal Sync

InvoiceDate: Click Type Icon (ABC) → Using Locale → Date (English US).

Bypasses localization errors and unifies mixed temporal arrays like 1/15/2025 and 2025-01-16.

QUESTION: Why fix dates if they already look correct to the human eye?

> ANSWER: If dates remain formatted as "Text", you cannot sort them chronologically (e.g., February 2024 would sort alphabetically before January 2024), nor can you extract Month/Year for period-over-period financial reporting.
6

Standardize Paths

DEPT (Replace Values)
  • Finance → FIN
  • Fin → FIN
  • Operations/Ops → OPS
  • Warehouse → WH
TERMS (Replace Values)
  • NET30/Net30 → Net 30
  • DOR → Due on receipt
  • NET15 → Net 15
7

Map The Tunnels (Merge)

  • Import New Source → Vendor_Alias_Map.csv.
  • Execute Use First Row as Headers. Clean VendorRaw column.
  • Return to AP_Raw. Execute Merge Queries (Left Outer) joining on Vendor.
  • Expand payload to extract only VendorName_Clean.
QUESTION: Why use a 'Left Outer' join instead of an 'Inner' join?

> ANSWER: An Inner Join drops any row that doesn't have a match. We can't just "delete" an invoice because a vendor was missing from our map—that understates liabilities! A Left Outer Join keeps all AP invoices and puts a "null" where mapping is missing, flagging it for review.
8

Master DB Uplink

  • Import New Source → Vendor_Master.csv. Clean VendorName.
  • Merge into AP_Raw linking via VendorName_Clean (Left Outer).
  • Expand payload to extract: VendorID, Category.
9

Fraud Trap Alg.

  • Import Purchase_Orders.csv and merge into AP_Raw via PO_Number. Expand PO_Amount.
  • Deploy Conditional Column POMatchStatus:
IF PO_Amount is null THEN "No PO"
ELSE IF Amount equals PO_Amount THEN "Match"
ELSE "Mismatch"
QUESTION: From an audit perspective, what does "No PO" indicate?

> ANSWER: It means the business spent money without getting pre-approval from procurement. This is a massive red flag for unauthorized spending, maverick purchasing, or potential fraud. It requires immediate manager review.
10

Duplicate Sweep

  1. Right-click AP_Raw → Duplicate query. Rename to DupCounts.
  2. Isolate VendorName_Clean and Amount (Remove others).
  3. Execute Group By. Operation: Count Rows.
  4. Merge DupCounts back into AP_Raw. Expand Count.
  5. Deploy Conditional Column DuplicateFlag: If Count > 1 then TRUE else FALSE.
QUESTION: Why group by BOTH Vendor and Amount? Is it possible for two distinct invoices to share an exact amount?

> ANSWER: Yes, recurring flat-fee services (like a $50/mo bill) will have identical amounts. However, seeing the exact same dollar amount billed by the exact same vendor on the same day is the mathematical fingerprint of a duplicate submission. It's a risk indicator, not a guarantee.
11

Final Extraction

  • Right-click AP_Raw → Reference. Rename to Exception_Report.
  • Filter to keep anomalies (Mismatches, Null Vendors, Duplicates).
  • Rename AP_Raw to Clean_AP_Transactions.
  • Execute: Close & Load To... (Table).
