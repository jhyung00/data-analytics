Absolute vs Relative Path (Alteryx — Visual + Quiz)

Absolute path = full address. Relative path = directions from where the .yxmd is saved. Below, the “real folder” view is a nested tree (ProjectFolder → Workflow/Data) like an actual computer.

Full address vs directions from the workflow

ABSOLUTE PATH = full address

Alteryx starts from the computer’s root (like C:\) and follows the entire path.

1
Workflow can be anywhere
C:\Users\YourName\Desktop\Workflows\my_workflow.yxmd
2
File is referenced by full location
C:\Users\YourName\Documents\ProjectFolder\Data\sales.xlsx
Visual: “Go to 123 Main St, Apt 4B.” (Exact address.)
Sharing problem: Students do not have C:\Users\YourName\... so it breaks.

RELATIVE PATH = directions from the workflow

Alteryx starts from the folder containing the .yxmd, then follows directions like “up one folder” (..).

Project folder (shared)
ProjectFolder/ ├─ Workflow/ │ └─ my_workflow.yxmd ← (START HERE) └─ Data/ └─ sales.xlsx
→
Relative path you type
..\Data\sales.xlsx
Meaning: “Go .. up to ProjectFolder/, then into Data/.”
Relative breaks if someone moves only the .yxmd (without keeping the same Data folder location).

How the path resolves
Key idea: Relative paths start from the folder that contains the .yxmd (Workflow folder).
Absolute paths start from the computer root (like C:\).

Where you type paths in Alteryx

In tools like Input Data, Directory, or Output Data, you provide a file/folder path.

Absolute (exact on your machine)
C:\Users\YourName\Documents\ProjectFolder\Data\sales.xlsx
Clear, but not portable across students.
Relative (portable if structure stays)
..\Data\sales.xlsx
Best for class packs / zipped project folders.
